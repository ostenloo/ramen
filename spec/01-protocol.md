# 01 — `ramen-proto`

Milestone M1. Pure types and codec. **No I/O in this crate.** No `tokio`, no
`std::fs`, no sockets. The codec operates on byte slices and buffers.

Dependencies permitted: `serde`, `serde_json`, `thiserror`, `ulid`. Nothing else.

## 1. Transport

`AF_UNIX` / `SOCK_STREAM`. The socket path is supervisor configuration and is
not part of this spec.

`SOCK_STREAM` (not `SOCK_DGRAM` or `SEQPACKET`) because the connection carries
authenticated session state established once at handshake, and because message
ordering within a session is load-bearing for the audit sequence.

## 2. Framing

Every message is:

```
+--------+------------------+
| u32 BE | payload (JSON)   |
+--------+------------------+
```

- The 4-byte prefix is the payload length in bytes, big-endian. It does **not**
  include the 4 prefix bytes.
- Payload is UTF-8 encoded JSON. No trailing newline. No compression.
- `MAX_FRAME_BYTES = 1_048_576` (1 MiB). A prefix declaring more is a fatal
  protocol violation: the supervisor **does not read the payload**, does not
  attempt to resynchronize, and terminates the connection. Attempting to skip
  ahead by the declared length trusts a value from an untrusted peer.
- A payload of length 0 is a fatal protocol violation.

Implement as `Codec` with two free functions plus an incremental decoder:

```rust
pub fn encode(msg: &impl Serialize, out: &mut Vec<u8>) -> Result<(), CodecError>;

pub struct Decoder { /* internal buffer */ }

impl Decoder {
    pub fn new() -> Self;
    /// Append bytes read from the transport.
    pub fn feed(&mut self, bytes: &[u8]) -> Result<(), CodecError>;
    /// Pop one complete frame's payload, if a whole frame is buffered.
    pub fn next_frame(&mut self) -> Result<Option<Vec<u8>>, CodecError>;
}
```

`feed` returns `Err(CodecError::FrameTooLarge)` as soon as a prefix exceeding
the limit is observed, before buffering the body. The decoder must be correct
across arbitrary chunk boundaries, including a prefix split across two `feed`
calls.

`CodecError` is fatal-only. Every variant terminates the connection. Recoverable
conditions are expressed in the envelope, not the codec.

```rust
pub enum CodecError {
    FrameTooLarge { declared: u32, max: u32 },
    ZeroLengthFrame,
    Utf8(/* ... */),
    Json(/* ... */),
}
```

## 3. Identifiers

- `RequestId` — ULID, generated by the client. **Single-use for the lifetime of
  the connection**: the supervisor rejects any reuse of a seen id, whether the
  first use is still in flight or already terminal. The supervisor's per-
  connection seen-set is capped at 65,536 entries; a connection that exceeds
  the cap is closed with `Fault` (§7). The supervisor does not require global
  uniqueness across connections and must not assume it.
- `SessionId` — ULID, generated by the supervisor at handshake. See D2 in
  `00-overview.md`.

Both serialize as their canonical string form. Newtype them; do not pass bare
`String`.

## 4. Version negotiation

`PROTOCOL_VERSION: u16 = 1`.

Every envelope carries `"v"`. The supervisor rejects any message whose `v` does
not exactly equal its own `PROTOCOL_VERSION`. There is no range negotiation and
no forward compatibility in v0. A mismatch on a request produces
`Error/VersionMismatch` and terminates the connection; a mismatch on `Hello`
produces a `Fault` (§7), because no request id exists yet.

Version negotiation is a thing to add when a second implementation exists and
cannot be upgraded in lockstep. Adding it now means maintaining compatibility
code paths that have never been exercised.

## 5. Handshake

The first frame on a connection must be `Hello`. Any other first message is a
fatal protocol violation.

**Client → supervisor:**

```json
{
  "v": 1,
  "type": "Hello",
  "token": "<base64url, no padding — serialized Biscuit>",
  "client": { "name": "ramenctl", "version": "0.1.0" }
}
```

`client` is advisory metadata for the audit log only. It is attacker-controlled
and must never influence an authorization decision. Cap each field at 64
bytes; over-length fields are **truncated, not fatal**, and the truncation is
recorded in the `SessionOpened` audit record (`02-audit.md` §4) via a
`truncated` flag. Truncation is not a protocol violation: a field that by
construction can never influence a decision does not warrant a fatal response.

**Supervisor → client, on success:**

```json
{
  "v": 1,
  "type": "Welcome",
  "session": "01J8Z...",
  "identity": "agent:planner",
  "capabilities": [
    { "op": "Whoami", "reversibility": "Trivial" },
    { "op": "FileWrite", "reversibility": "Trivial",
      "constraints": { "path_prefix": ["/Users/austin/work"] } }
  ]
}
```

`capabilities` is the guard's own evaluation of what this token permits — a
convenience for clients, **not** a grant. Presence in this list is neither
necessary nor sufficient for a later operation to be authorized: every operation
is authorized independently at call time. Implementations must not cache it as
policy.

**Supervisor → client, on failure:** a `Fault` envelope (§7) followed by
connection close. Handshake failure is always terminal. There is no retry on the
same connection. (A failed `Hello` has no request id, so `Error` — which always
carries an id — cannot be used here.)

## 6. Request envelope

```json
{
  "v": 1,
  "id": "01J8ZQ...",
  "op": { "type": "Whoami" }
}
```

```rust
pub struct Request {
    pub v: u16,
    pub id: RequestId,
    pub op: Operation,
}

#[derive(Serialize, Deserialize)]
#[serde(tag = "type", deny_unknown_fields)]
pub enum Operation {
    Whoami(WhoamiOp),
    FileWrite(FileWriteOp),
}

// An *empty* struct, not a unit variant: an internally-tagged unit variant
// silently accepts unknown fields (serde drops them), which would violate the
// rule below. Wrapping the payload is what makes `deny_unknown_fields` apply.
#[derive(Serialize, Deserialize)]
#[serde(deny_unknown_fields)]
pub struct WhoamiOp {}
```

Use `#[serde(deny_unknown_fields)]` on every request-side struct. An unknown
field is a fatal protocol violation, not something to ignore. Silently dropping
fields is how a client comes to believe it constrained an operation that the
supervisor executed unconstrained.

Operation payloads are defined in `05-operations.md`.

### Reversibility

```rust
#[derive(Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
pub enum Reversibility { Trivial, Compensable, Irreversible }
```

Reversibility is a **static property of the operation type**, not a runtime
computation and not client-supplied. Expose it as:

```rust
impl Operation {
    pub fn reversibility(&self) -> Reversibility;
}
```

The guard may require different authorization for different classes. Because it
is static, adding an operation forces an explicit classification decision at
compile time — which is the point.

## 7. Response envelope

Three terminal statuses, tagged on `status`:

```json
{ "v": 1, "id": "01J8ZQ...", "status": "Ok",     "result": { ... } }
{ "v": 1, "id": "01J8ZQ...", "status": "Denied", "denial": { ... } }
{ "v": 1, "id": "01J8ZQ...", "status": "Error",  "error": { ... } }
```

All three are terminal for that request id. There is no non-terminal status in
v0: `Pending` was cut (see D1 and "Deliberately faked in v0" in
`00-overview.md`), and a client that sees an unrecognized status returns a
transport-level error rather than waiting. A client must not assume response
order matches request order; responses are matched by id.

### `Fault` (connection-level)

```json
{
  "v": 1,
  "type": "Fault",
  "error": { "code": "Internal", "message": "connection limit reached" }
}
```

`Fault` is a message type of its own, distinct from the request/response
envelopes:

- It carries **no `id`**. A `Fault` is about the connection, not a request.
  `Error`-status responses always carry an id; a `Fault` never does. This keeps
  "connection-level fault" versus "this request failed" a type distinction
  rather than a null check that clients will forget.
- It is always terminal and always followed by close.
- It is sent on: fatal violations (best-effort final frame, §8), connection
  cap reached (`03-supervisor.md` §3), and request-id seen-set overflow
  (`03-supervisor.md` §5).
- Its error codes are the same closed set as `Error` responses.

### `Denied` vs. `Error` — keep these distinct

**`Denied`** means the guard evaluated the request and the answer was no. The
system worked correctly. This is a policy outcome.

**`Error`** means the machinery failed: malformed input, an unavailable
subsystem, an I/O failure during execution.

Collapsing these makes the audit log useless for the question it exists to
answer — whether the enforcement model is holding — because a flood of denials
(possible attack) becomes indistinguishable from a flood of I/O errors (possible
disk failure).

```json
{
  "status": "Denied",
  "denial": {
    "code": "CapabilityNotGranted",
    "reason": "token grants no FileWrite capability",
    "audit_seq": 1041
  }
}
```

`audit_seq` is the sequence number of the audit record for this denial. It lets
an operator correlate a client-visible denial with the log without trusting the
client's account of what happened.

Denial codes (closed set; add variants deliberately):

| Code | Meaning |
|---|---|
| `CapabilityNotGranted` | No capability in the token covers this operation type. |
| `ConstraintViolated` | A capability exists but a caveat rejected these arguments. Catch-all for unclassifiable denials (04 §5). |
| `ReversibilityNotPermitted` | Token does not authorize this reversibility class. |
| `ControlPlaneProtected` | Target resolves inside Ramen's own state. Invariant 5. |
| `TokenExpired` | Token failed a time-based check. |

```json
{
  "status": "Error",
  "error": { "code": "NotImplemented", "message": "operation not available in v0" }
}
```

Error codes: `VersionMismatch`, `MalformedRequest`, `NotImplemented`,
`IdentityUnverifiable`, `AuditUnavailable`, `ExecutionFailed`, `Internal`.

**The code sets are closed, per protocol version.** Both the denial codes
and the error codes are closed sets for v0: the lists above are normative, and
a conforming client rejects a frame carrying an unrecognized code exactly as
it rejects an unrecognized envelope `type` or response status (a transport
error). A new code is a protocol change and ships with a new `v`; because the
version is validated before the body is parsed (§3, §8), a conforming client
never has to parse an unknown code. Do not extend a set within a version —
that is what a version bump is for.

`AuditUnavailable` is unreachable from a v0 supervisor: an audit failure is a
process fatal (`00-overview.md` invariant 4), so a client whose audit-append
just failed sees a closed connection, not this code. The code stays in the set
so a client built against this version remains forward-compatible with a
supervisor that might one day answer rather than exit.

**`message` must never contain data derived from the operation's target
contents.** It may name a path the client already supplied; it must not contain
file bytes, environment values, or key material. A supervisor that echoes
content in error text becomes a read oracle for callers who are not authorized
to read.

## 8. Fatal violations

On any of these, the supervisor writes a `ProtocolViolation` audit record,
attempts to send a final `Fault` on a best-effort basis, and closes the
connection:

- frame length over `MAX_FRAME_BYTES`, or zero
- payload not valid UTF-8, or not valid JSON
- `v` mismatch
- first message not `Hello`
- `Hello` after handshake completes
- unknown field in a request struct
- reuse of a request id already seen on the connection

The supervisor does not attempt to resynchronize a stream. Once framing is in
doubt, every subsequent byte is untrusted.

Note: over-length `client` fields are **not** fatal (truncated, §5).

## 9. Acceptance criteria (M1)

- [ ] `cargo test -p ramen-proto` passes; crate has `#![forbid(unsafe_code)]`.
- [ ] Round-trip property test: any `Request` encodes and decodes identically.
- [ ] Decoder correctness across chunk boundaries, including a length prefix
      split 1/3, 2/2, and 3/1 across `feed` calls.
- [ ] `feed` rejects an over-large prefix without buffering the body — assert on
      internal buffer size, not just on the error.
- [ ] Unknown field in a request is rejected, with a test naming the field.
- [ ] A JSON payload with duplicate keys is handled deterministically; assert the
      chosen behavior explicitly rather than inheriting `serde_json`'s default
      by accident.
- [ ] `Operation::reversibility()` is exhaustive — adding a variant without
      classifying it fails to compile. Verify by inspecting for a wildcard arm;
      there must not be one.
- [ ] Golden-file tests: at least one serialized example per envelope variant
      (`Hello`, `Welcome`, `Request` per operation, `Ok`, `Denied`, `Error`,
      `Fault`) committed as a fixture. These are the regression net for
      accidental wire changes and must be updated only in a commit that also
      updates this spec.
- [ ] No dependency outside the permitted set. Verify with `cargo tree`.
